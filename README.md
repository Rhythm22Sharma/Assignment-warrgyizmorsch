# Credit Card Fraud Risk Assessment: Reference Implementation & Rigorous Evaluation

A complete, standalone machine learning reference implementation for credit card fraud risk assessment. Built with an **observation / outcome window cohort design**, tie-preserving risk labeling, strict zero-leakage user cross-validation protocols, probability calibration, automated Pydantic input validation, model provenance metadata, and continuous drift monitoring.

> **Data & Operational Context Notice:**  
> The underlying dataset is derived from the simulated Kaggle Credit Card Fraud Detection dataset (Kartik2112 simulator). The target risk label is derived strictly from the outcome window. All unit economic cost figures mentioned are **illustrative assumptions** for operational framing.

## 5. Modeling Assumptions & Documented Limitations

1. **Derived Future Target:** Risk labels are computed exclusively from the user's fraud rate in the **outcome window (last 40% of timeline)**. The ground-truth risk category is not a static property of the cardholder, but a forward-looking empirical rate.
2. **Simulated Transaction Dynamics:** The dataset is generated from a synthetic simulator (`kartik2112`). Patterns reflect simulated agent behaviors rather than organic credit card networks.
3. **Quality Filter Selection Effect:** Users with `< 10` transactions in the outcome window (17 users) and users with zero observation activity (16 users) were excluded to eliminate extreme small-sample rate variance ($1/2 = 50\%$). The final modeled population is **908 cardholders**.
4. **150-Transaction Observation Cap:** Historical transactions per user were capped at 150 random observation-window rows (yielding 136,200 observation transactions) to guarantee sub-two-minute pipeline execution while preserving per-card representation.
5. **Outcome Label Invariant:** The outcome risk label is fixed per user across all their observation rows; single transactions do not have distinct future risk labels.

## 6. Recommended Model Choice & CV Selection Rationale

### Selection Protocol (CV / Validation Evidence Only)
In accordance with strict evaluation protocols, the production model was selected **solely on cross-validation and validation set evidence**, never on test set performance:
- **CV Feature Comparison:**
  - *Base Features (10 vars):* 5-Fold CV High-Risk PR-AUC = **$0.1112 \pm 0.0326$**, Macro F1 = **$0.3145 \pm 0.0197$**
  - *Base + Past-Only Features (17 vars):* 5-Fold CV High-Risk PR-AUC = **$0.1156 \pm 0.0307$**, Macro F1 = **$0.3180 \pm 0.0113$**
  - **Decision:** The difference ($+0.0044$) is well within one standard deviation of cross-validation noise ($\sim 0.031$). Because past-only features do not beat base features beyond CV noise, the simpler **Base-Feature model** is recommended (Occam's razor). This allows single-transaction scoring in production without requiring callers to maintain multi-month rolling transaction histories.
- **Model Architecture & Hyperparameters:**
  - **LightGBM (`class_weight='balanced'`, `learning_rate=0.05`, `max_depth=4`)**
  - *Note on Hyperparameters:* Deeper trees (`max_depth=6`, Macro F1: $0.3344$) and SMOTE (Macro F1: $0.3546$) achieved higher CV macro F1, but the model was selected on high-risk PR-AUC ($0.1112$ vs $0.1105$ and $0.1068$). Because differences across configurations are within one standard deviation of CV noise, the simplest configuration (depth 4, balanced class weights, no SMOTE) was chosen.
- **Probability Calibration:**
  - **Isotonic Calibration** achieved superior probability calibration on validation users (Validation Brier Score: **$0.0840$**, vs Uncalibrated **$0.1435$** and Platt **$0.0860$**).
- **Operating Threshold:**
  - **$th = 0.1288$** (tuned strictly on **validation users only** to maximize $F_2$ subject to precision $\ge 0.15$).

To test whether legitimate historical fraud feedback carries predictive power across temporal windows, an optional feature \past_fraud_count_lagged\ was computed strictly on transactions occurring within the **observation window** prior to each transaction:

| Split | Model | Feature Set | Calibration | Threshold | 5-Fold CV Macro F1 | 5-Fold CV High-Risk PR-AUC |
| :---: | :--- | :--- | :--- | :--- | :---: | :---: |
| **[5-Fold CV]** | LightGBM (depth=4) | 10 Base Features | None | Default (.50$) | .3145 \pm 0.0197$ | .1112 \pm 0.0326$ |
| **[5-Fold CV]** | LightGBM (depth=4) | 10 Base + Past Features | None | Default (.50$) | .3180 \pm 0.0113$ | .1156 \pm 0.0307$ |
| **[5-Fold CV]** | LightGBM (depth=4) | Base + \past_fraud_count_lagged\ | None | Default (.50$) | **.4105 \pm 0.0219$** | **.1489 \pm 0.0399$** |

*Key Takeaway:* Prior confirmed fraud in the observation window meaningfully increases CV PR-AUC to .1489$ (+0.0377). However, in production this relies on chargebacks having settled (a 30-90 day lag), so it cannot be computed for recent real-time transactions. The primary production pipeline therefore retains only the 10 real-time base transaction features.

### Note on PR-AUC Differences Across Tables
Uncalibrated tree models output unique continuous leaf values yielding smooth precision-recall curves (e.g. PR-AUC = $0.1777$ on raw test features). When Isotonic Calibration is applied, probabilities are grouped into piecewise-constant step bins (ties), which flattens the precision-recall curve and shifts discrete PR-AUC ($0.1166$). Threshold tuning moves the operating cutoff point without altering the continuous area under the curve.

## 13. The Main Result: Empirical Proof of Data Leakage

| Evaluation Regime | Accuracy | Macro F1 | High-Risk Recall | High-Risk Precision | High-Risk PR-AUC |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **(a) Baseline Random Row Split (Leaky)** | **98.59%** | **0.9862** | **100.00%** | **98.70%** | **0.999965** |
| **(b) User-Level Split (Disjoint Users)** | **47.44%** | **0.3366** | **19.29%** | **23.60%** | **0.177658** |
| **[LEAK TEST] Static Features on (a) Random Split** | **99.80%** | **0.9982** | **100.00%** | **100.00%** | **1.000000** |
| **[LEAK TEST] Static Features on (b) User Split** | **47.96%** | **0.3301** | **14.29%** | **25.88%** | **0.168017** |

> **The Central Finding:** When a model is trained exclusively on static cardholder demographics (`lat, long, city_pop, age`), it achieves **1.0000 PR-AUC** on a random split because coordinates uniquely fingerprint individual cards. On unseen users, it collapses to **0.1680 PR-AUC**. Random row splitting creates a dangerous illusion of near-perfect accuracy by enabling models to memorize entity fingerprints rather than learning fraud behavior.
